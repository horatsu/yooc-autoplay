# 易班优课 · 课群课程自动连播

[![Tampermonkey](https://img.shields.io/badge/Tampermonkey-4.0%2B-orange?logo=tampermonkey&logoColor=white)](https://www.tampermonkey.net/)
[![License](https://img.shields.io/badge/license-MIT-blue)](./LICENSE)
[![Platform](https://img.shields.io/badge/platform-YOOC%20%C2%B7%20yiban-2ea44f)](https://yooc.me/)

一个 Tampermonkey 用户脚本：在易班优课（YOOC）的课群课程学习页，按左侧章节目录顺序**完整播放**每一节，一节播完自动进入下一节，本页目录全部播完即停止。

> 定位是「省手，不省时间」。脚本只替你点按钮，不替你消耗时长。

---

## 边界声明

这个脚本**只做 UI 层自动化**，三件事明确不做：

| | 说明 |
|:--|:--|
| 不改 `currentTime` | 不拖进度条、不跳结尾。视频按真实时长一秒一秒播完。 |
| 不伪造上报请求 | 不碰 `saved_video_position` / `done` 这类心跳接口，进度由播放器自己上报。 |
| 不处理防挂机弹窗 | 中途出现确认框时脚本会停下等待，而非自动点掉。 |

这样做的原因很直接：平台后端记录的是每节课的实际播放时长，管理员可见。绕过播放器直接灌一条 `done: true` 会在后台留下「时长 0 秒但显示完成」的异常数据。本脚本产生的记录与实际观看行为一致。

---

## 功能

- **自动连播**：按目录顺序逐节播放，播完自动切下一节
- **等加载完再播**：视频 `readyState < 2` 时不点播放，避免播放器空转被记成无效播放
- **切节留缓冲**：本节播完后等 5 秒再点下一节，新页面静置 2.5 秒后才介入
- **进度自恢复**：页面跳转或无刷新切节后自动接续，无需重新启动
- **图文课件跳过**：目录项没有视频时，等待后自动跳过，不会卡死
- **跨 frame 协调**：播放器位于 iframe 内时，通过 `postMessage` 与顶层页面协同
- **自动播放降级**：被浏览器自动播放策略拦截时，自动降级为静音播放
- **卡住自愈**：检测到播放停滞超过 8 秒时尝试恢复
- **悬浮控制面板**：实时显示「第 n / N 节 · 百分比 · 已播 / 总时长」，支持折叠

## 安装

1. 在浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox 均有官方版本）
2. 将 [`yooc-autoplay.user.js`](./yooc-autoplay.user.js) 拖入浏览器窗口，Tampermonkey 会弹出安装页
   - 或：点击扩展图标 → 添加新脚本 → 清空编辑器 → 粘贴全文 → `Ctrl+S`
3. 确认脚本处于启用状态

## 使用

1. 打开易班优课 → 我的课群 → 课群课程 → 学习课程
2. 右下角出现「优课连播」面板，点击「开始连播」
3. 面板显示进度，全部播完后自动停止并提示

详细图文说明见 [`docs/guide.html`](./docs/guide.html)。

## 工作原理

脚本需要在两种页面形态下工作：播放器在顶层文档里，以及播放器被包在 iframe 里。目录结构又因页面版本而异。主要处理三个问题。

### 一、目录识别：三级兜底

平台的课程目录没有稳定的 class 名，因此按可靠性递减依次尝试：

```
① a[href*=courseware]        —— 指向课件页的链接，最可靠
② a[href*=chapter|section]   —— 退一步按语义关键词匹配
③ 容器推断                    —— 在 [class*=chapter|catalog|outline] 内取 li
④ 单项目录                    —— 仅当该项 URL 与当前地址一致时才认定
```

每一级都要先剔除噪声：站点导航、面包屑、页脚，以及「上一节 / 下一节」这类翻页按钮（它们同样指向课件页，会被误判为目录项），并按 `href` 去重——这一步让上一节/下一节的链接与目录中同一节的链接合并为一条。

### 二、当前节点定位

要判断「现在该播第几节」，依次尝试：

1. 归一化 URL 匹配（去协议、去 hash、去尾斜杠后比对）
2. 活跃状态类名（`active` / `current` / `selected` / `playing`，含后代元素）
3. `sessionStorage` 中记录的索引（应对无刷新切节）

三者全部失败时**不从第 0 节猜起，而是保持未定位状态**，由调用方从第 1 节开始。宁可重播，不可漏播。

### 三、重复触发防护

视频结束信号在真实环境里并不可靠：`ended` 可能不触发，`timeupdate` 可能连续多次越线，SPA 切节还可能让同一元素复用。因此做了三层保护：

- **完成判据**：`ended || currentTime >= duration - 0.6`，且要求 `duration >= 4s`（过滤片头动画）
- **幂等键**：以 `document.URL | currentSrc | duration` 拼接指纹，同一指纹只处理一次
- **切节冷却**：点击下一节后进入 7 秒冷却期，期间到达的完成信号**不丢弃，挂起至冷却结束后补执行**（早期版本直接丢弃，遇到短课件会永久卡死）

若冷却结束后检测到 URL 与视频指纹均未变化，判定点击未生效并自动重试一次。

## 配置

脚本顶部的 `CFG` 对象：

```js
var CFG = {
  rate: 1,               // 播放倍速，1 = 原速
  endSlack: 0.6,         // 距结尾多少秒判定为播完
  minDuration: 4,        // 短于该秒数的视频不当作一节课
  noVideoWaitMs: 15000,  // 无视频课件等待多久后跳过
  nextDelayMs: 5000,     // 播完后等多久切下一节
  pageSettleMs: 2500,    // 新页面静置多久再介入
  readyTimeoutMs: 90000, // 视频就绪最长等待，超时才强制播放
  handoffMs: 7000,       // 切节冷却，防连点
  debug: true            // 控制台日志，稳定后可关闭
};
```

`nextDelayMs`、`pageSettleMs`、`readyTimeoutMs` 这三个都是为了让播放器把视频真正加载出来再动手。网络慢的话把它们继续调大即可，调大只会更稳。

倍速会真实改变视频的实际播放时长。若课群按「有效时长 ≥ 视频总时长 × 比例」判定，倍速可能导致不达标——**默认 1.0 倍是最安全的选择**。

## 常见问题

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 面板不出现 | 不在匹配域名下或脚本未启用 | 确认地址为 `*.yooc.me` |
| 日志打印「未识别到课程目录」 | 页面结构不在预设选择器内 | 提 issue 附 DOM 结构 |
| 播完不切下一节 | `ended` 未触发或时长读取异常 | 检查控制台是否有「本节播放完成」 |
| 反复从第 1 节开始 | 当前节点定位失败，走了兜底逻辑 | 属预期行为（宁可重播）；可手动「跳过本节」 |
| 视频不自动播放 | 浏览器自动播放策略 | 脚本会自动降级静音；仍失败则手动点一次 |
| 卡在某一节 | 该节为图文/测验，或存在确认弹窗 | 等待 15 秒自动跳过，或手动「跳过本节」 |

调试：按 `F12` 打开控制台，筛选 `[优课连播]` 前缀的日志。
